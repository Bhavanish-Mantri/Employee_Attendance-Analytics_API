# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `app/main.py:22-23` | Synchronous client creation at module import without lifespan management, ping check, or timezone awareness (`tz_aware=True`). | Application crashes on import if MongoDB container starts slightly after app, or returns naive UTC datetimes breaking boundary conversions. | Configured lifespan context manager with idempotent index creation and `tz_aware=True`. |
| 2 | `compute_late_minutes` (`app/main.py:33-37`) | Evaluated `minutes > 10` instead of checking if punch-in is strictly > 10:00 (600s) past shift start. | A punch-in at 09:40:01 for a 09:30 shift returned 0 late minutes instead of 10 because `int(601/60) = 10` is not `> 10`. | Calculated difference in seconds: if `diff_sec > 600`, return `int(diff_sec // 60)`, else 0 per R2. |
| 3 | `compute_work_hours` (`app/main.py:40-41`) | Used Python builtin `round()`, which performs banker's rounding (round half to even). | Values like 8.875 or 8.865 produce banker's rounding discrepancies against the required half-up standard. | Implemented `quantize_half_up` using Python `decimal.Decimal` with `ROUND_HALF_UP` per R4 and R8. |
| 4 | `compute_overtime` (`app/main.py:44-47`) | Did not enforce the minimum 30-minute threshold; mixed tz-aware and naive datetimes. | Punch-out 15 minutes after shift end returned 15 overtime minutes instead of 0 per R3. | Verified `(punch_out - shift_end).total_seconds() >= 1800`; otherwise returns 0 per R3. |
| 5 | `health` (`app/main.py:72-74`) | Returned static `{"status": "ok"}` without pinging MongoDB. | Returns 200 OK even when MongoDB is offline or unreachable. | Executed `client.admin.command("ping")` and returns HTTP 503 if unreachable. |
| 6 | `create_employee` (`app/main.py:78-85`) | Check-then-insert race condition on `emp_code`. | Concurrent requests with the same `emp_code` passed `find_one` and caused unhandled crashes or duplicate documents. | Enforced database unique index on `emp_code` and caught `DuplicateKeyError` to return HTTP 409. |
| 7 | `create_employee` (`app/main.py:82`) | Stored `created_at` as local naive datetime and returned datetime rather than epoch milliseconds. | Response `created_at` was not an integer epoch millisecond per OpenAPI `EpochMillis` schema. | Stored UTC datetime truncated to seconds and returned integer epoch milliseconds. |
| 8 | `EmployeeIn` (`app/main.py:53-60`) | Missing input validation for `emp_code` format, email pattern, and `shift_start != shift_end`. | Allowed identical shift start and end times, violating assessment constraint. | Added Pydantic schema validation matching OpenAPI regexes and checked `shift_start != shift_end` (HTTP 422). |
| 9 | `list_employees` (`app/main.py:93`) | Off-by-one pagination bug: `skip = page * page_size`. | Requesting `page=1` skipped items 0..19, omitting the entire first page of employees. | Fixed pagination offset to `skip = (page - 1) * page_size` per R10. |
| 10 | `list_employees` (`app/main.py:94`) | Counted entire collection (`count_documents({})`) ignoring active filter. | Requesting `GET /employees?department=Sales` returned total count of all employees in company. | Passed filter query `count_documents(query)` so `total` accurately reflects applied filters per R10. |
| 11 | `list_employees` (`app/main.py:95`) | Missing deterministic sort order. | Employees returned in arbitrary natural order instead of sorted by `emp_code` ascending. | Added `.sort("emp_code", ASCENDING)` to MongoDB query. |
| 12 | `punch_in` (`app/main.py:100-121`) | Check-then-insert race condition on `(emp_code, date)`. | Simultaneous punch-in requests created duplicate logs for the same employee and date. | Created compound unique index on `(emp_code, date)` and caught `DuplicateKeyError` to return HTTP 409. |
| 13 | `punch_in` (`app/main.py:102-103`) | Used local server timezone instead of IST; failed overnight shift date assignment. | An overnight worker (22:00–06:00) punching in at 05:00 IST was assigned the wrong attendance date. | Converted punch instant to IST and assigned punch-ins earlier than `shift_end` to previous day per R1. |
| 14 | `punch_in` (`app/main.py:101`) | Did not check if employee exists before punch-in. | Punching in for an unknown `emp_code` crashed with `KeyError` (HTTP 500) at `emp["shift_start"]`. | Checked `emp_code` presence; returns HTTP 404 if employee does not exist. |
| 15 | `punch_in` (`app/main.py:119`) | Exposed internal MongoDB id as `"id": str(res.inserted_id)`. | Response payload violated `AttendanceRecord` schema which strictly forbids `id`/`_id`. | Removed `id` field from response and formatted payload strictly against OpenAPI schema. |
| 16 | `list_attendance` (`app/main.py:144-150`) | Fetched entire collection into Python memory with `list(db.attendance_logs.find(q))` and sorted/sliced in Python. | On ~100k records, caused massive memory consumption, blocking latency, and potential OOM crash. | Performed indexed sort `[("date", -1), ("emp_code", 1)]` and pagination (`skip`/`limit`) inside MongoDB. |

### Non-Defects Examined
- **BSON Date storage in MongoDB vs Epoch Milliseconds in API:** We examined whether MongoDB should store integers or BSON datetimes. `DATA_MODEL.md` explicitly specifies BSON date storage in MongoDB and epoch ms in the API boundary. This separation was maintained and correctly converted at boundaries.
- **Handling of absent/leave records:** We verified whether punch-in should create `ABSENT` or `LEAVE` records. Per contract, punch-in only accepts `PRESENT`, `WFH`, `ON_DUTY`; `ABSENT` and `LEAVE` are created exclusively via back-office seeds or regularization.
